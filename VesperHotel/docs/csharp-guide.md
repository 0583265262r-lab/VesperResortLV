# איך לקרוא את הבקנד

הדוגמה לסגנון היא הפרויקט [Operational Activity Monitoring Platform](https://github.com/mordechay0tzvi-svg/Operational-Activity-Monitoring-Platform). במיוחד: `RestApi/Pipeline/Pipeline.cs`, ‏`RestApi/Dbs/DbContext.cs` ו־`RestApi/Models/Station.cs`.

בחרנו לשמור על המבנה המוכר: מחלקות עם Properties, בנאי שמקבל תלויות, ושירות שמבצע שאילתות דרך EF Core. הפרויקט לדוגמה שימש לקביעת רמת הקוד; הוא לא שונה ולא הוכנס כתלות.

## מסלול של בקשה

```text
React form
    -> API controller
    -> BookingService
    -> HotelDbContext
    -> database
```

ה־Controller קורא את הבקשה, מזהה את המשתמש ומחזיר תשובה. `BookingService` בודק את החוקים ומבצע את הפעולה. `HotelDbContext` הוא החיבור של EF Core למסד הנתונים.

## דפוסים מוכרים

בפרויקט לדוגמה יש יצירת שאילתה עם `AsQueryable`, הוספת `Where` בתוך `if`, ולבסוף `ToListAsync`. אותו רעיון משמש לסינון הזמנות: מתחילים משאילתה, מסננים לפי משתמש, סטטוס וטווח תאריכים, ואז מוסיפים מיון ועימוד.

מחלקת שירות מקבלת את מה שהיא צריכה דרך הבנאי. אין צורך ליצור DbContext חדש מתוך כל פונקציה או להחזיק חיבור סטטי. ASP.NET יוצר את השירותים בהתאם לרישום ב־Dependency Injection.

`CancellationToken` מאפשר להפסיק עבודה כשבקשה בוטלה או כשהשרת נסגר. `await` ממתין לקריאה למסד או לרשת בלי לחסום Thread למשך כל ההמתנה.

## למה הזמנה דורשת טרנזקציה

בדיקת זמינות רגילה מתאימה להצגה למשתמש. בעת שמירה, שני משתמשים יכולים לראות את אותו חדר פנוי. לכן בודקים שוב בתוך טרנזקציה שמחזיקה נעילה מתאימה.

```text
פתיחת טרנזקציה
נעילת המלאי
בדיקת זמינות עדכנית
שמירת ההזמנה והאירוע
Commit
```

אם הפעולה נכשלת לפני Commit, השינויים מתבטלים. הנעילה נמצאת במסד הנתונים כדי שגם שני תהליכי API שונים יפעלו בצורה עקבית.

`DatabaseWrite` מרכז את ההבדל בין MySQL לבין SQLite. אין צורך לפזר את פקודות הנעילה בכל Controller.

## למה יש Idempotency

אם האתר שולח בקשה והחיבור נופל, לא תמיד אפשר לדעת אם ההזמנה נשמרה. האתר שולח שוב עם אותו מפתח, והשרת מחזיר את תוצאת הפעולה המקורית. המפתח וההזמנה נשמרים יחד. אותו מפתח עם תוכן אחר הוא שגיאה.

## למה יש Outbox

שמירת הזמנה ופרסום ל־Kafka הן שתי פעולות במערכות שונות. כדי שלא לאבד אירוע, שומרים אותו קודם במסד הנתונים יחד עם ההזמנה. Worker קורא את האירוע ומפרסם אותו מאוחר יותר. אם הפרסום נכשל, אפשר לנסות שוב.

אירוע עשוי להגיע פעמיים. טבלת Inbox שומרת אילו אירועים כבר עובדו. זו הסיבה שה־Consumer לא מסתפק בהפעלת הפעולה בכל פעם שמתקבלת הודעה.

## למה שומרים סכומי כסף בסנטים

בקוד ובמסד הנתונים נשמר מספר שלם של סנטים, למשל `25000` עבור 250 דולר. זה מאפשר לחשב ולסכם סכומים באופן עקבי גם ב־MySQL וגם ב־SQLite. ב־API המחיר מוצג כסכום דולרי רגיל. המרה מתבצעת בפונקציה אחת שמוודאת שהמחיר תקין.

## סדר מומלץ לשינוי קטן ראשון

כדי להוסיף שדה לתיאור חדר, התחל במודל, הוסף אותו למיפוי ולתשובת ה־API, ואז הצג אותו בממשק. כדי לשנות חוק ביטול, התחל ב־BookingService ובכלל המדיניות, והוסף בדיקה לתאריך הגבול. אל תשנה את אותו כלל בנפרד ב־Controller וב־React.

## מה פושט מהתכנון המקורי

אין מסגרת CQRS, ‏MediatR או Repository כללי שעוטף כל פעולה של EF. שירותים ברורים מרכזים את הפעולות. התשתיות המתוחכמות יותר קיימות רק במקומות שבהם הן פותרות בעיה ממשית: נעילות, בקשות חוזרות, אירועים והרשאות.
