# VESPER Hotel

מערכת הזמנות וניהול למלון בדיוני בלאס וגאס. האתר כולל חדרים, פעילויות ותחבורה, חשבון משתמש, שמירת מקום זמנית, אישור וביטול הזמנות, וממשק ניהול למלאי, למחירים ולהיסטוריית הפעולות.

הבקנד נכתב בסגנון הקרוב לפרויקט Operational Activity Monitoring Platform ששימש כדוגמה: מחלקות רגילות, בנאים מפורשים, הזרקת תלויות, שירותים שמשתמשים ב־DbContext, שאילתות LINQ ו־async/await. מנגנוני הטרנזקציות והרקע מופרדים כדי שתהליך ההזמנה יהיה קריא.

## הפעלה מקומית עם Docker Compose

זוהי דרך ההפעלה הראשית של המערכת. דרוש Docker Desktop כשה־Linux engine פעיל. מתוך תיקיית הפרויקט:

```powershell
pwsh -File scripts/start-docker.ps1
```

או ישירות עם הפקודה הרגילה של Compose, לאחר הרצה חד־פעמית של `scripts/initialize-env.ps1`:

```powershell
docker compose --env-file .env up --build
```

הסקריפט מריץ `docker compose up --build`, יוצר סודות מקומיים אם חסרים, וממתין שכל השירותים יהיו בריאים. ההרכב כולל את האתר, API, ‏Worker, ‏MySQL, ‏Kafka, ‏Elasticsearch ו־Kibana.

- אתר: http://localhost:8080
- API: http://localhost:5080/api/health
- כניסת מנהל: http://localhost:8080/admin/login
- משתמש מנהל: `admin@vesper.local`
- סיסמת המנהל נוצרת אקראית ונשמרת בשדה `ADMIN_PASSWORD` בקובץ `.env` המקומי. אין סיסמה קבועה בקוד.
- ניתן להירשם דרך האתר כדי לבדוק את חוויית האורח.
- מזג האוויר מגיע מ־Open-Meteo ומוצג בעמוד הבית.
- לכל חדר תמונת שער וגלריית תמונות משלו במסך פרטי החדר.

לעצירה:

```powershell
pwsh -File scripts/stop-docker.ps1
```

הנתונים והסיסמאות נשמרים גם אחרי העצירה. מידע נוסף על הסקריפטים, המשתנים והלוגים נמצא ב־[מדריך ההפעלה](infrastructure/README.md).

## מצב פיתוח קל ללא Docker

למי שרוצה לעבוד רק על הקוד במהירות, דרושים .NET 10 SDK, ‏Node.js ו־pnpm:

```powershell
pwsh -File scripts/start-local.ps1
```

מצב זה משתמש ב־SQLite ומציג את האתר ב־http://localhost:5173. הוא נועד לפיתוח מקומי מהיר ואינו כולל MySQL, ‏Kafka או Elasticsearch.

## מה המערכת עושה

| תחום | התנהגות |
| --- | --- |
| חדרים | הקצאת חדר פיזי לכל התקופה, לפי תפוסה ותאריכי כניסה ויציאה |
| פעילויות | מועדים נפרדים וקיבולת משתתפים לכל מועד |
| תחבורה | הקצאת רכב פיזי עם מרווח תפעולי לאחר הנסיעה |
| הזמנות | שמירה לעשר דקות, אישור, ביטול, פקיעה והשלמה אוטומטית |
| מחיר | חישוב בשרת ושמירת המחיר ותנאי הביטול בזמן ההזמנה |
| חשבון | הרשמה, כניסה, רענון התחברות, פרופיל, איפוס סיסמה והודעות |
| ניהול | מלאי, מחירים, מועדים, הזמנות, משתמשים, דשבורד ולוג ביקורת |
| אירועים | Outbox מתמשך, ניסיונות חוזרים, מניעת עיבוד כפול ועבודות רקע |

המלון, המחירים והצילומים הם נתוני הדגמה. ההזמנות הן במודל תשלום במלון; אין סליקה או חיוב כרטיסים. הדשבורד מציג שווי הזמנות ולא כסף שנגבה.

## כללים עסקיים

- זמני המלון מחושבים לפי `America/Los_Angeles`.
- כניסה לחדר ב־15:00 ויציאה ב־11:00. הזמנה נמשכת 1–30 לילות.
- שמירת מקום זמנית צורכת מלאי ופגה לכל המאוחר בתחילת השירות.
- תחבורה מחויבת לפי מספר שעות בעיגול כלפי מעלה, עם 30 דקות להתארגנות לאחר הסיום.
- ביטול עצמי של חדר אפשרי עד 48 שעות לפני הכניסה. בפעילות ובתחבורה עד 24 שעות לפני ההתחלה.
- מנהל יכול לבצע ביטול חריג לפני השלמה עם סיבה מתועדת.
- השבתת משאב מונעת הזמנות חדשות ושומרת על ההיסטוריה.
- שינוי מחיר לא משנה מחיר שנשמר בהזמנה קיימת.
- אישור הזמנה אינו תשלום, והשלמת הזמנה אינה אישור לגביית כסף.

## מאיפה להתחיל לקרוא את הקוד

1. `src/Hotel.Api/Models` — האובייקטים, בקשות ה־API וכללי ההזמנה.
2. `src/Hotel.Api/Data` — ה־DbContext, הטבלאות, הנתונים הראשוניים והטרנזקציה.
3. `src/Hotel.Api/Services/CatalogService.cs` — חיפוש וזמינות.
4. `src/Hotel.Api/Services/BookingService.cs` — יצירת הזמנה ושינוי הסטטוס.
5. `src/Hotel.Api/Controllers` — הכתובות שהאתר פונה אליהן וההרשאות.
6. `src/Hotel.Api/Program.cs` — רישום כל השירותים והפעלת השרת.
7. `src/Hotel.Worker` — עבודות הרקע, Kafka ו־Elasticsearch.
8. `frontend/hotel-web/src` — מסכי האתר וחיבורם ל־API.

[מדריך קריאת הבקנד](docs/csharp-guide.md) מסביר את חלוקת האחריות ואת ההבדלים מהפרויקט ששימש כדוגמה.

## בדיקות

לאחר הפעלה על מסד נתונים מקומי המיועד לבדיקות:

```powershell
node tests/api-smoke.mjs
```

הבדיקה יוצרת חשבונות ומלאי בדיקה, בודקת הרשאות, מחיר שננעל, בקשות חוזרות ומלאי מקביל, ומכבה בסיום את משאבי הבדיקה. אין להריץ אותה על מלון פעיל. תוצאות האימות בפועל מפורטות ב־`docs/verification.md`.

מיגרציות MySQL נמצאות ב־`src/Hotel.Api/Migrations`. במצב הפיתוח המקומי SQLite נוצר אוטומטית באמצעות `EnsureCreated`, ולכן אין פרויקט migrations נוסף.

## פרטים תפעוליים

מסד הנתונים הוא מקור האמת. Kafka ו־Elasticsearch הם רכיבי עיבוד ותצפית. הגדרות רגישות נשמרות במשתני סביבה וב־`.env` שאינו מיועד ל־Git. הודעות במצב הפיתוח נכתבות לקבצים מקומיים ואינן נשלחות לאנשים אמיתיים. יש לחבר ספק דיוור לפני שימוש ציבורי.

לפני פרסום ציבורי נדרשים סביבת HTTPS, גיבויים, שירות הודעות, סודות מנוהלים ואימות תפעולי של תשתית הייצור. פרטי סביבת Docker ומגבלותיה מתועדים במדריך ההפעלה.
